## 根因与实现

BIN-153已证实上传、写库和落盘成功。读取失败由图片无 Authorization 头及上传后 URL 生成 `//profile/...` 两层叠加导致。

源码还显示 `UploadedFileAccessService.read` 在允许展示头像之前先调用 `SecurityUtils.getUserId()`；因此只放开 SecurityConfig 仍会被后续文件授权层拦截。

| 文件 | 最终变化及影响 |
|---|---|
| `qdata-framework/qdata-security/.../SecurityConfig.java` | 仅为 `GET /profile/avatar/**` 增加 permitAll。HEAD、POST、PUT、PATCH、DELETE和上传接口不获得此放行；其他 `/profile/**` 继续要求认证。 |
| `qdata-framework/qdata-security/.../AuthenticationEntryPointImpl.java` | `/profile` 及 `/profile/**` 拒绝认证时返回真实HTTP401及原JSON结构，包含 Accept:text/html 场景，不回退SPA壳。其他业务API保留既有HTTP200+业务401及SPA导航契约，避免改变 Axios 登录过期处理。 |
| `qdata-module-da/qdata-module-da-biz/.../UploadedFileAccessService.java` | 将既有有效用户头像检查移到登录检查前，SQL原文不变。只允许真实路径位于头像目录、扩展名属于既有图片白名单、且被未删除用户精确引用的文件匿名读取。无引用图片、HTML、指向ETL的软链接不公开；其他文件的项目/所有者校验不变。 |
| `qdata-ui/src/utils/avatar.mjs` | 新增共享头像解析函数；复用既有 `joinApiPath` 归一化边界斜杠，保留 HTTP(S) 绝对URL与缺省头像语义。 |
| `qdata-ui/src/store/system/user.js` | getInfo 使用共享解析函数，保留缺省头像回退。 |
| `qdata-ui/src/views/sys/system/user/profile/userAvatar.vue` | 上传成功后与store使用同一URL；closeDialog清理visible ref；上传拒绝时显示已有多语言失败提示并保留裁剪框以便重试。 |
| `qdata-server/src/test/.../AvatarReadSecurityTest.java` | 新增真实Spring Security过滤链、JWT过滤器、文件授权服务、拦截器及资源控制器组合测试；数据库和令牌查询是离线替身。 |
| `qdata-ui/tests/avatar.test.mjs` | URL组合、真实Vue响应式/Pinia与实际组件脚本测试；API、裁剪回调、弹窗提示和i18n是替身。 |

Java路径表省略了公共包前缀 `src/main/java/tech/qiantong/qdata/`，完整列表见交付补丁。

## 兼容与安全边界

- 沿用头像上传字段 `avatarfile`、接口响应 `imgUrl`，没有接口契约、SQL、表结构、角色或数据范围模型变更。
- 头像目录不代表无条件公开：匿名访问只服务仍被有效用户引用的图片；旧头像无引用时继续拒绝。原有 `SafeUploadPath` 实路径检查、单次解码、防跨目录访问、nosniff和私有缓存头保留。
- 未使用Cookie令牌回退；未改变TokenService。

- 未操作任何Hive/HDFS数据；未修改yangbin数据、密码、角色；未改插件/JDBC、质量规则或既有调度任务。
